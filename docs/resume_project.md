# 简历项目描述 — 企业级客服一线支撑 Agent 系统

## 项目经历

**企业级客服一线支撑 Agent 系统（全流程自研）**      AI应用开发工程师      2025.07 - 至今

**解决什么问题：**
客服一线高频场景（退款/退货/补发/赔付/活动咨询/转人工）存在三个核心痛点：一是客服回答不统一、质量参差，人工处理量大；二是检索不到答案时 LLM 容易 hallucinate，给出错误政策；三是低置信度问题无人工兜底，导致客诉升级。本系统通过"规则优先 + LLM 增强 + 自动建单"的三段式架构，在保证不编造的前提下，让机器人承担常规咨询，人工只处理真正需要介入的问题。

**核心成果：**
- 意图分类准确率 **98.2%**（1000 条测试集含边界值/对抗样本/多轮追问），ticket/return/reship 三类意图达到 100%，CI **57 个测试用例全通过**，改 prompt 前后指标可对比回归。
- 累计处理会话 170+，工单 11,355 条（售后 2,952、运营 816、质检 516、通用 7,071），平均置信度 0.61，低置信度问题自动触发建单，人工只需处理紧急工单 1,658 条。
- 搭建 RAG 检索链路（ChromaDB + DeepSeek Embedding），支持本地 hash embedding 双路自动降级，检索失败不中断服务；知识库文档热更新无需重启。
- 设计三层工程护栏：按用户 ID 令牌桶限流（10 req/s）、operator/supervisor/admin 三级权限隔离、运行时灰度开关一键回滚（规则版 ↔ LLM 版意图分类）。
- 自研可观测层：SQLite 直算工单统计/LLM Token 成本/置信度均值并推送告警，配套 5 个前端页面（问答/工单/监控/评估/审计），支持全链路 trace 查看。
- 搭建 badcase 自动回流机制，改 prompt 前后可对比回归，避免盲改。

**技术栈：** Python 3.10 / FastAPI / LangGraph / ChromaDB / DeepSeek / SQLite / Pytest，独立负责需求-设计-开发-测试-部署全流程。

## 面试可展开的技术亮点

**1. 意图分类 98.2% 是怎么达成的**
- 规则版（nodes.py）覆盖 7 类强信号关键词，对清晰意图命中率高
- LLM 版通过灰度开关 `USE_LLM_INTENT=1` 启用，作为规则版的补充和升级
- 两者之间设计了自动降级：LLM 返回非法标签或调用失败时，自动回退到规则版
- 修复了两个 bug：① refund/return 规则混淆（"退"字优先匹配 refund），② clarify 节点错误覆盖原始 intent
- return 意图从 0% 修正到 100%

**2. 1000 条测试集怎么设计的**
- 按 7 类意图×多表达变体参数化组合生成（天数/商品类型/口语程度）
- 边界值扫描：签收 5/7/8/10/15/20/30/60 天连续扫描，补发次数 1-5 次
- 对抗样本：错别字（"退kuan""腿款"）、混英文（"refund my order"）、超长句、空输入、随机字符
- 多轮追问：每类意图接 10 个后续追问，覆盖真实对话场景
- 修复 refund/return 规则 bug 后，reship/return 达到 100%

**3. 工程护栏的设计思路**
- 限流：内存令牌桶，按 user_id 独立计数，默认容量 10 请求/秒补充 2 个
- 权限：ROLE_PERMISSIONS 字典驱动，operator 只能 chat/list，supervisor 可改工单状态，admin 可回滚
- 灰度：FeatureFlags 读进程级内存桶 → 环境变量 → dataclass 默认值，三级优先级，写操作加锁
